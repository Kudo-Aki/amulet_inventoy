# Googleフォーム連携ガイド（入荷・出荷・棚卸・商品登録 → 在庫反映 → ラベルPDF自動送付）

このガイドでは、Googleフォームから入荷・出荷・棚卸・商品登録を行うと在庫に自動反映され、入荷時には箱に貼るラベル（QR付き）のPDFが入力者にメールで届く機能のセットアップと運用方法を説明します。あわせて、在庫を上書きする操作の前に自動で取られるバックアップと、そこからの復元についても説明します。

既存の機能（QRスキャンによる納品・出庫・棚卸、管理画面の各機能）はそのまま使えます。この機能は「追加」であり、Googleスプレッドシート連携（API設定）が前提です。

---

## 1. できること

| 操作 | 結果 |
|---|---|
| **入荷**フォームを送信（商品と箱数を最大10商品） | 在庫が「箱数×入数」だけ増え、履歴に記録。発注状況の分納も納期が早い順に自動で消し込み。**箱ラベルのPDFが入力者宛にメールで届く**（Driveにも保存） |
| **出荷**フォームを送信（商品と箱数・端数を最大3商品） | 在庫が減り、履歴に記録。安心在庫を下回った場合は入力者と管理者にメールで通知 |
| **棚卸**フォームを送信（商品と実在庫数を最大10商品） | **反映前に自動でバックアップ**を取ったうえで、送った商品だけ在庫がその数に置き換わる。送っていない商品は変わらない。差異は履歴に記録 |
| **商品登録**フォームを送信 | 商品マスタに追加され、他のフォームの選択肢にも反映。初期在庫を入れれば在庫の計上まで済む |
| アプリを開く・「🔄 更新」 | フォームで反映された在庫・履歴が表示される |
| 納品モードでスキャン | フォームで入荷登録済みの箱は「入庫済」として自動で除外され、二重計上を防ぐ（API有効時） |
| QRコード発行画面 | 箱台帳から次の番号を自動取得。「PDFをメールで送る」でPCが無くても印刷できる |
| 管理画面の「バックアップと復元」 | バックアップの世代を選び、**変更点を確認してから**復元できる。復元自体も取り消せる |

処理の流れ:

```
Googleフォーム（入荷 / 出荷 / 棚卸 / 商品登録）
   │ 送信
   ▼
スプレッドシート（フォーム回答_入荷 / _出荷 / _棚卸 / _商品登録 シート）
   │ 自動（フォーム送信トリガー。取りこぼしは10分毎に再処理）
   ▼
GAS が 商品管理シート（現在庫・発注状況）と 履歴シート を更新
   ├─ 入荷: 箱台帳に箱番号を採番して「入庫済」で登録 → ラベルPDFを作成して Drive に保存 → 入力者へ PDF 添付メール
   ├─ 出荷: 安心在庫を下回れば通知メール
   ├─ 棚卸: 反映の前に バックアップ台帳／明細 へ1世代ぶん控えてから上書き
   └─ 商品登録: 商品管理に追加し、全フォームの選択肢を更新
   ▼
アプリ（index.html / 管理画面）は起動時・更新時にシートから読み直す
```

## 2. 初回セットアップ（PC推奨・約15分）

### 2-1. Apps Script にファイルを追加する

1. [script.google.com](https://script.google.com/) で、既にお使いの「お守り在庫管理」プロジェクトを開きます。
2. リポジトリの `gas/` フォルダにある次のファイルを、同じ名前で追加します（「＋」→「スクリプト」→ 名前を入力 → 内容を貼り付け）。
   - `FormIntegration.gs`
   - `LabelPdf.gs`
   - `LabelTemplate.gs`
   - `QRCode.gs`
   - `Tests.gs`
3. 既存の `Code.gs` を `gas/Code.gs` の内容で置き換えます。変更点は3つだけです。
   - `doGet` の `default:` で拡張アクションに委譲する
   - `data` パラメータの解釈順を修正（備考に「%」が含まれるとデータが空になる不具合の修正）
   - 見積メール・起案書の署名（神社名・氏名・連絡先）を「設定」シートから読むように変更
4. 左メニューの「サービス」に **Drive API**（v2）があることを確認します。無ければ「＋」から追加します（起案書作成を使っていれば追加済みです）。
5. 保存します。

> `appsscript.json` を表示している場合は、`gas/appsscript.json` と同じ内容（timeZone `Asia/Tokyo`、Drive v2）になっているか確認してください。

### 2-2. セットアップ関数を実行する

1. エディタ上部の関数選択で `setupFormIntegration` を選び「実行」します。
2. 初回は権限の承認画面が出ます。フォーム・スプレッドシート・Drive・Gmail の権限を許可してください。
3. 実行ログに作成結果が出ます。以下が作られます。
   - スプレッドシートに `設定` `入力者` `箱台帳` `バックアップ台帳` `バックアップ明細` `フォーム回答_入荷` `フォーム回答_出荷` `フォーム回答_棚卸` `フォーム回答_商品登録` シート
   - Googleフォーム「お守り入荷登録」「お守り出荷登録」「お守り棚卸登録」「お守り商品登録」（Drive の `お守り在庫管理_ラベルPDF` フォルダ内）
   - ラベル用の A4縦 Googleスライド テンプレート
   - トリガー（フォーム送信時 / 毎朝6時の選択肢同期 / 10分毎の未処理再処理 / 毎日のバックアップ）

> **既にセットアップ済みの場合も、もう一度 `setupFormIntegration` を実行してください。**
> 既にあるフォーム・シート・トリガーはそのまま残り、足りないもの（棚卸・商品登録フォーム、バックアップ用シート）だけが追加されます。

> ラベルテンプレートについて「ページサイズが A4縦 になりませんでした」と表示された場合は、ログに出た Googleスライドを開き「ファイル › ページ設定 › カスタム 21cm × 29.7cm」に変更してから、もう一度 `setupFormIntegration` を実行してください。

### 2-3. シートを記入する

**入力者シート**（フォームのプルダウンとPDFの送付先）

| 名前 | メール | 有効 | 備考 |
|---|---|---|---|
| 山田 | yamada@example.com | TRUE | |
| 佐藤 | sato@example.com | TRUE | |

- 「名前」がフォームの選択肢になります。同じ名前を2行に書かないでください。
- 「有効」を FALSE にすると選択肢から外れます。

**設定シート**（主な項目）

| キー | 内容 |
|---|---|
| adminEmail | エラー通知の送信先。入力者にメールが無い場合の PDF 送付先にもなります |
| orgName / senderName / senderShortName / senderEmail / senderAddress / senderTel / senderFax / senderMobile | 見積依頼メールと起案書の署名（これまでコードに直書きされていた内容。**必ず記入してください**） |
| offsetX_mm / offsetY_mm | ラベル印字位置の微調整（mm）。右・下が＋ |
| maxBoxesPerLine / maxBoxesPerSubmission | 1商品・1送信あたりの箱数上限（既定 50 / 80） |
| maxInventoryCount | 棚卸で1商品に入力できる実在庫数の上限（既定 100000。桁の入力ミス対策） |
| lowStockMail | 出荷で安心在庫を下回ったらメール通知（TRUE/FALSE） |
| labelFontFamily | ラベルの日本語フォント（既定 Noto Sans JP） |

**バックアップの設定**（値を変えるだけで効きます。再デプロイもトリガーの作り直しも要りません）

| キー | 既定 | 内容 |
|---|---|---|
| maxBackups | 30 | 保持する世代数。超えた分は古い順に消えます |
| backupBeforeFormInventory | TRUE | 棚卸フォームの反映前に自動でバックアップ |
| backupBeforeAppInventory | TRUE | 管理画面の棚卸し反映前に自動でバックアップ |
| backupBeforeStockSave | **FALSE** | 管理画面「在庫を保存」の前にもバックアップしたい場合は TRUE |
| dailyBackup | **FALSE** | 毎日決まった時刻に自動バックアップしたい場合は TRUE |
| dailyBackupHour | 3 | 毎日バックアップの時刻（0〜23） |

記入後、エディタで `syncFormChoices` を実行すると、フォームの「入力者」「商品」のプルダウンが更新されます（管理画面の「選択肢を同期」ボタンでも可）。

### 2-4. 試し刷りで位置を確認する

1. エディタで `test_sampleLabelPdf` を実行します。ログに PDF の URL が出ます。
2. PDF をエーワン 31266（A4・8面）に印刷します。プリンター設定は「実際のサイズ（100%）」、「ページに合わせる」はオフにしてください。
3. ズレがあれば `設定` シートの `offsetX_mm` / `offsetY_mm` に mm 単位で入力し、もう一度試し刷りします。
4. 印刷したラベルをアプリの納品モードで読み取れることを確認します。

### 2-5. Web アプリを新しいバージョンでデプロイする

管理画面にフォームの URL や状態を表示するには、Web アプリの再デプロイが必要です。

1. 「デプロイ」→「デプロイを管理」→ 鉛筆（編集）→ バージョン「新バージョン」→「デプロイ」
2. URL は変わりません（アプリ側の API 設定はそのままで大丈夫です）。
3. 管理画面「⚙️ 管理メニュー」→「API設定」→「Googleフォーム連携」で「状態を更新」を押し、フォームの URL が表示されれば完了です。

## 3. 日常の運用

### 入荷のとき

1. スマホで入荷フォームを開きます（管理画面の「Googleフォーム連携」に URL と QR コードがあります。QR を印刷して倉庫に貼っておくと便利です）。
2. 入力者を選び、届いた商品と箱数を入力して送信します（1回で最大10商品）。
3. 1〜2分でラベルPDFがメールで届きます。印刷して各箱に貼ってください（左上から順に、番号はメール本文に記載）。
4. 在庫・履歴はこの時点で反映済みです。**納品モードでのスキャンは不要です**（スキャンしても「入庫済」として除外され、二重計上にはなりません）。

### 出荷のとき

1. 出荷フォームを開き、入力者・商品・箱数（端数があれば個数）・出荷先を入力して送信します。
2. 在庫が減り、安心在庫を下回った場合はメールで通知されます。

### 棚卸のとき

1. 棚卸フォームを開き、入力者を選び、**数えた商品と実際の個数**を入力して送信します（1回で最大10商品）。
2. 反映の前に自動でバックアップが取られ、送った商品の在庫がその数に置き換わります。送っていない商品は変わりません。
3. 差異は履歴に記録されます（差異がゼロの商品は履歴を書きません）。
4. 回答シートの「バックアップ」列に、その回答の反映前バックアップIDが入ります。戻したいときはこのIDを使ってください。

> **空欄と 0 は意味が違います。**
> 空欄＝「数えていない」（在庫を触りません）／ `0` ＝「在庫ゼロ」（0個として反映します）。
> 商品だけ、あるいは実在庫数だけを入力するとエラーになります（入れ忘れを黙って捨てないためです）。

一度に数え切れないときは、何回かに分けて送れば構いません。送るたびにその回に入力した商品だけが更新されます。

### リストにない商品が見つかったとき

1. 商品登録フォームを開き、商品名・商品コード・入数を入力して送信します。
2. 今ある個数が分かっていれば「初期在庫」に入れてください。登録と在庫の計上が1回で済みます。
3. 1分ほどで、入荷・出荷・棚卸フォームの商品プルダウンにも出てきます。

> **商品コードは英大文字のみ 1〜12文字**（例: `KOTSU`、`ANZAN`）。
> 数字・小文字・記号・スペース・全角は使えません。QRラベル（`商品コード-年-箱番号`）の読み取りが
> この形を前提にしているためで、破ると以後に作った商品のスキャンが一切通らなくなります。
> 規則から外れたコードはエラーで差し戻されます（勝手に直したりはしません）。

### 在庫を戻したいとき（バックアップからの復元）

1. 管理メニュー →「API設定」→「バックアップと復元」を開きます。
2. 戻したい世代を選び、**戻す範囲**を決めます。
   - **在庫のみ**（既定）: 現在庫と安心在庫だけを戻します。棚卸のやり直しはこちらで十分です
   - **すべて**: 商品名・入数・単価・発注先・発注状況まで戻します
3. 「🔍 変更点を確認」を押すと、**何がどう変わるか**が一覧で出ます。ここで内容を確かめてください。
4. 「♻️ この内容で復元」を押すと反映されます。
5. 復元の直前の状態も自動で控えられます。結果に出る「取り消し用」のIDを同じ範囲で復元すれば、復元そのものを取り消せます。

復元の性質:

- バックアップに無い商品（そのあと追加された商品）は**触りません**
- バックアップにあって今の商品管理に無い商品は**復活させません**（消した商品が勝手に戻らないように）
- 商品コード（A列）は変えません。照合キーとして使います
- 復元は履歴シートには書きません。記録は「バックアップ台帳」に残ります

### アプリで確認するとき

- 管理画面「在庫管理」の「🔄 更新」を押すと最新の在庫・履歴が表示されます。
- 回答シート（`フォーム回答_入荷` / `_出荷` / `_棚卸` / `_商品登録`）の右側の列に、処理結果・反映内容・ラベル番号範囲・PDF URL・バックアップ が記録されます。

### 商品や入力者を変えたとき

- 商品マスタ編集で保存すると、フォームの商品プルダウンは自動で更新されます。
- 入力者シートを変更したら、管理画面の「選択肢を同期」を押してください（毎朝6時にも自動で同期されます）。

## 4. 困ったとき

| 症状 | 確認・対処 |
|---|---|
| フォームを送ったのに在庫が変わらない | 回答シートの「処理結果」列を確認。空なら管理画面の「未処理の回答を再処理」を押す。「エラー」ならエラー列の内容を確認（商品が選択肢に無い、箱数が上限超過など）。管理者にもメールが届きます |
| 「在庫反映済/PDF失敗」になった | 在庫は反映済みです。PDF だけ作り直すには、エディタで `resendLabelPdfAction_({ row: 行番号 })` を実行するか、QRコード発行画面の「PDFをメールで送る」で同じ番号範囲を指定して送ります |
| PDF が届かない | 入力者シートのメールアドレス、`設定` の adminEmail を確認。Gmail の送信上限（無料アカウントは1日あたり約100通）に達していないか確認。PDF は Drive の `お守り在庫管理_ラベルPDF` フォルダにも保存されています |
| ラベルの位置がずれる | 「実際のサイズ（100%）」で印刷しているか確認し、`offsetX_mm` / `offsetY_mm` で調整 |
| フォームの選択肢が古い | 管理画面の「選択肢を同期」または `syncFormChoices` を実行 |
| 管理画面に「フォーム連携の情報を取得できませんでした」と出る | GAS に FormIntegration.gs 等が追加され、**新しいバージョンでデプロイ**されているか確認 |
| 同じ箱番号が重複した | 箱台帳シートで確認。QRコード発行画面では「台帳の次番号を取得」を使うと重複しません。古い端末の発行履歴は「発行履歴を箱台帳へ登録」で移行できます |
| 棚卸を間違えて送ってしまった | 回答シートの「バックアップ」列にあるIDを、管理画面の「バックアップと復元」で選び、「変更点を確認」→「この内容で復元」 |
| 商品登録が「エラー」になった | エラー列を確認。商品コードが英大文字1〜12文字か、既に使われていないか（大文字小文字の違いも重複として弾きます）、入数が1以上かを確認してください |
| 商品登録が「登録済/選択肢同期失敗」になった | 商品は登録済みです。管理画面の「選択肢を同期」を押してください（毎朝6時にも自動で同期されます） |
| 復元したい世代が一覧に無い | 保持世代数（設定シートの `maxBackups`、既定30）を超えて削除された可能性があります。世代を増やすには値を大きくしてください |
| 管理画面で在庫を保存したら「サーバー側でも変わっています」と出た | この画面を開いたあとに、同じ商品がフォームや別の端末から更新されています。表示された値を見て、画面の値で上書きしてよければ続行してください |

## 5. 仕組みの補足（管理者向け）

- **冪等性**: 回答行の「処理結果」が空の行だけを処理します。トリガーが二重に発火しても在庫が二重に増えることはありません。
- **棚卸の処理順**: 「解析 → バックアップ → 書き込み」の順です。入力ミスで解析に失敗しただけの回答がバックアップ世代を1つ消費して、本当に必要な世代を押し出すのを防いでいます。
- **バックアップの持ち方**: シートを複製するのではなく、商品管理の行を「バックアップ台帳」「バックアップ明細」に行として貯めます。シートの複製は使用範囲ではなくグリッド全体（既定1000×26＝26,000セル）を複製するため、30世代でブックのセル上限の約8%を占めてしまうためです。行方式なら30世代で約0.3%です。
- **在庫の保存**: 管理画面の在庫保存・棚卸し反映は、**画面を開いた時点から変わった商品だけ**をシートへ送ります。全件を送らないので、画面を開いたあとにフォームから入荷があっても巻き戻りません。
- **排他**: 在庫・履歴・発注・箱台帳の更新は排他ロック内で行い、PDF作成とメール送信はロックの外で行います（在庫の反映を最優先）。
- **箱番号**: `商品コード-年（西暦下2桁）-箱番号（4桁）`。年は入荷日（未入力なら送信日）から決まり、番号は箱台帳の同じ商品・年の最大値＋1から採番します。
- **発注の消し込み**: アプリの納品モードと同じく、納期が早い分納から順に消化し、すべて消化すると「未発注」に戻ります。シート上の納期は `M/D` 形式（年なし）のため当年として扱います。
- **QR画像**: 外部サービスに送らず GAS 内で生成します（`QRCode.gs`、MIT ライセンスの Kazuhiko Arase 版）。
- **ラベルPDF**: Google スライド（A4縦）に pt 単位で配置して PDF 化します。用紙はエーワン 31266（97×69mm、8面）。
- **個人情報**: 署名などはスプレッドシートの `設定` シートにのみ保存され、リポジトリのコードには含まれません。
